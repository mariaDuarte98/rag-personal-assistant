Vector Databases

A vector database stores high-dimensional embeddings and supports efficient similarity search. Rather than looking up records by exact key, you query by semantic similarity — "find the documents closest to this query vector."

ChromaDB:
ChromaDB is an open-source, embedded vector database. It runs in-process (no separate server) and persists data to disk using a PersistentClient. Collections hold documents, embeddings, and optional metadata. The `upsert` method is idempotent — re-running ingestion updates existing records rather than duplicating them.

Similarity search:
ChromaDB uses cosine similarity or L2 distance to rank results. The `n_results` parameter controls how many top matches are returned. For small collections, querying is fast; for large ones, approximate nearest-neighbour (ANN) algorithms like HNSW are used internally.

Metadata filtering:
Every document in ChromaDB can store metadata (e.g., source filename, chunk index, date). You can filter results by metadata at query time, for example to restrict search to a specific document or date range.

Embeddings:
The quality of retrieval depends heavily on the embedding model. `all-MiniLM-L6-v2` from sentence-transformers is a compact, fast model that produces 384-dimensional vectors. Larger models (e.g., `all-mpnet-base-v2`) produce better embeddings at higher computational cost.

Use cases:
- Semantic search over private documents
- Long-term memory for conversational AI
- Recommendation systems
- Duplicate detection
